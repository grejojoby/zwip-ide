# SQL Server connections and stored procedures

Install and enable the **SQL databases 0.2.0** package, then choose **Database → New… → Microsoft SQL Server**. Enter a host, TCP port (1433 by default), database name, SQL login, and password. Passwords use macOS Keychain. Windows integrated authentication, Entra authentication, named-instance discovery, and `GO` batch separators are not supported; use the instance's TCP port and select one batch at a time.

TLS and certificate verification are enabled by default. **Trust server certificate (skip verification)** is an explicit option for servers with certificates you cannot validate. Configure this only for a server you trust.

In the SQL console, select text and press **Cmd+Enter** (or **Ctrl+Enter**) to run only that text. Without a selection, the shortcut and **Execute** run the entire console. Results are paged, up to 500 rows per page; different SQL Server result sets retain their own columns and result-set number. **Next result page** advances through pages and result sets. **Cancel / close query** cancels the owned request. Query sessions close after completion and are not shared between executions.

Tables and views are discovered from SQL Server catalogs. Grid edits use a transaction and original-value preconditions, and require a primary key and only integer, bit, character, or uniqueidentifier column types. Tables containing other types are read only in the grid; explicit SQL remains available. Driver decoding can round high-precision decimal/money values or date/time precision; cast sensitive values to text in queries when exact representation matters. Preview limits apply after driver decoding.

Choose **Stored procedures…**, filter by schema/name, and select a procedure. The read-only viewer shows its `MS_Description`, SQL definition, and parameter names, types, OUTPUT flags and parameter descriptions. SQL parameter defaults remain visible in the definition; SQL Server does not reliably expose T-SQL defaults in `sys.parameters`. Missing documentation is explicit. A missing definition may mean encryption, a CLR procedure, or insufficient `VIEW DEFINITION` permission. The list contains only procedures visible to the login in the connected database. Definitions above 1 MiB are rejected with an explicit error. This viewer never executes procedures.

The SQL worker adds `procedures {connectionId}` and `procedureDetails {connectionId, schema, procedure}` operations to `tool.request`. The core resolves credentials and routes SQL Server requests to the SQL package. Schema and procedure names are bound parameters for metadata lookups. SQL Server-specific implementation stays inside the package; the core stores only connection metadata.
